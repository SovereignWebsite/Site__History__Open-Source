Security and sustainability

The promise that many eyes make bugs shallow, and what happened when critical projects turned out to have very few eyes on them.

  1. May 1997 Free software

    The promise: given enough eyeballs, all bugs are shallow.

    Raymond coined "Linus's Law": given enough eyeballs, all bugs are shallow.

    Or, less formally, ``Given enough eyeballs, all bugs are shallow.'' I dub this: ``Linus's Law''.

    Primary source: document The Cathedral and the Bazaar: Release Early, Release Often, Eric S. Raymond (catb.org), by Eric S. Raymond, published May 1997. Read 27 November 2026.

    The wording and the name are Raymond's, not Torvalds's. Text read is version 3.0 of the essay.

    Connects: Eric S. Raymond, Linus Torvalds, The Cathedral and the Bazaar

    Link to this fact

  2. 7 April 2014 Mainstream

    Heartbleed: a serious flaw in a library the internet depends on.

    In April 2014 the Heartbleed bug in the open source OpenSSL library exposed information protected by the encryption that secures much of the internet.

    The Heartbleed Bug is a serious vulnerability in the popular OpenSSL cryptographic software library. This weakness allows stealing the information protected, under normal conditions, by the SSL/TLS encryption used to secure the Internet.

    Primary source: report The Heartbleed Bug, Codenomicon (heartbleed.com), published 2014. Read 27 November 2026.

    The date is that of the fixed release: the same page says "OpenSSL 1.0.1g released on 7th of April 2014 fixes the bug."

    Connects: Heartbleed

    Link to this fact

  3. 2014 Mainstream

    Industry funds critical projects in response.

    The Linux Foundation founded the Core Infrastructure Initiative in response to Heartbleed, to fund critical open source projects.

    The Linux Foundation’s Core Infrastructure Initiative (CII), founded in response to the 2014 Heartbleed bug

    Primary source: press-release Technology and Enterprise Leaders Combine Efforts to Improve Open Source Security, Open Source Security Foundation (The Linux Foundation), published 3 August 2020. Read 27 November 2026.

    Stated in the Linux Foundation's 2020 announcement of the Open Source Security Foundation; the original April 2014 press release is no longer at its address (404).

    Connects: The Linux Foundation, Open Source Security Foundation, Heartbleed

    Link to this fact

  4. 3 August 2020 Strain and stewardship

    The effort is consolidated in the Open Source Security Foundation.

    In August 2020 the Linux Foundation formed the Open Source Security Foundation, folding in the Core Infrastructure Initiative; Microsoft, Google, IBM, Red Hat and GitHub were among its founding board members.

    It combines efforts from the Core Infrastructure Initiative, GitHub’s Open Source Security Coalition and other open source security work from founding governing board members GitHub, Google, IBM, JPMorgan Chase, Microsoft, NCC Group, OWASP Foundation and Red Hat, among others.

    Primary source: press-release Technology and Enterprise Leaders Combine Efforts to Improve Open Source Security, Open Source Security Foundation (The Linux Foundation), published 3 August 2020. Read 27 November 2026.

    Connects: The Linux Foundation, Open Source Security Foundation, GitHub, Google, IBM, Microsoft, Red Hat

    Link to this fact

  5. December 2021 Strain and stewardship

    Log4Shell: a critical flaw in a ubiquitous logging library.

    The Log4Shell vulnerability (CVE-2021-44228) in the Apache Log4j logging library allowed attackers to run arbitrary code; Apache rates it 10.0, critical.

    JNDI lookup can be exploited to execute arbitrary code loaded from an LDAP server

    Primary source: report Apache Logging Services: Security (vulnerability reports), The Apache Software Foundation. Read 27 November 2026.

    From the Apache Logging Services security page, which lists the CVSS score as "10.0 CRITICAL" and credits Chen Zhaojun of Alibaba Cloud Security Team with the discovery. The page gives no disclosure date; December 2021 is from the CVE number and the wider record. The CISA statement returned 403.

    Connects: Apache Group and Apache Software Foundation, Log4Shell

    Link to this fact

  6. 29 March 2024 Strain and stewardship

    A deliberate backdoor is found in xz.

    On 29 March 2024 Andres Freund reported to the oss-security list that the xz compression library had been backdoored upstream, in a way that compromised SSH servers.

    The upstream xz repository and the xz tarballs have been backdoored.

    Primary source: mailing-list backdoor in upstream xz/liblzma leading to ssh server compromise, oss-security mailing list (Openwall), by Andres Freund, published 29 March 2024. Read 27 November 2026.

    Connects: Andres Freund, The xz backdoor

    Link to this fact

  7. 10 December 2024 Strain and stewardship

    The European Union legislates on software security.

    The European Union's Cyber Resilience Act entered into force on 10 December 2024, with its main obligations applying from 11 December 2027.

    The CRA entered into force on 10 December 2024. The main obligations introduced by the Act will apply from 11 December 2027, with reporting obligations to apply as of 11 September 2026.

    Primary source: document Cyber Resilience Act, European Commission. Read 27 November 2026.

    Connects: European Union, Cyber Resilience Act (Regulation (EU) 2024/2847)

    Link to this fact

  8. 10 December 2024 Strain and stewardship

    The law gives open source foundations a defined role.

    The Act creates a new legal category, the open source software steward, for bodies that sustain open source products used commercially, under a lighter regime than manufacturers.

    the novel legal category of open-source software stewards is introduced. These are legal persons who provide support on a sustained basis for the development of such products which are intended for commercial activities, and who play a main role in ensuring their viability, and are subject to a light-touch and tailor-made regulatory regime.

    Primary source: document The Cyber Resilience Act and open source, European Commission. Read 27 November 2026.

    From the European Commission's explanatory page. The text of the Regulation on EUR-Lex returned a 202 challenge page and could not be read with the fetch tool.

    Connects: European Union, Cyber Resilience Act (Regulation (EU) 2024/2847)
