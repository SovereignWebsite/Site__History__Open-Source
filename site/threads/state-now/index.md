# Where things stand

The open questions of 2018 to 2026, each from the statements of the parties.

### 16 October 2018: MongoDB said the one substantive change in the SSPL was that anyone offering MongoDB as a service must open source the software used to run that service.

Step 1. The vendors' complaint: cloud providers sell their software as a service.

> The only substantive change is an explicit condition that any organization attempting to exploit MongoDB as a service must open source the software that it uses to offer such service.

- Source (primary, press-release): [MongoDB Issues New Server Side Public License for MongoDB Community Server](https://www.mongodb.com/company/newsroom/press-releases/mongodb-issues-new-server-side-public-license-for-mongodb-community-server), MongoDB, Inc., published 16 October 2018. Read 27 November 2026.
- Connects: MongoDB, Inc., Server Side Public License
- Fact id: `mongodb-sspl-cloud-reason-2018`

### 1998: Criterion 6 of the Open Source Definition forbids a licence from restricting the fields in which a program may be used, including use in a business.

Step 2. The rule their new licences break.

> The license must not restrict anyone from making use of the program in a specific field of endeavor. For example, it may not restrict the program from being used in a business, or from being used for genetic research.

- Source (primary, document): [The Open Source Definition](https://opensource.org/osd), Open Source Initiative. Read 27 November 2026.
- Note: Quoted from the current text of the definition. This is the clause the OSI cites against licences that restrict cloud providers.
- Connects: Open Source Initiative, The Open Source Definition
- Fact id: `osd-no-field-discrimination`

### 19 January 2021: On 19 January 2021 the Open Source Initiative stated that the SSPL is not an open source licence, calling such licences "fauxpen" source.

Step 3. The OSI's ruling.

> Fauxpen source licenses allow a user to view the source code but do not allow other highly important rights protected by the Open Source Definition, such as the right to make use of the program for any field of endeavor.

- Source (primary, press-release): [The SSPL is Not an Open Source License](https://opensource.org/blog/the-sspl-is-not-an-open-source-license), Open Source Initiative, published 19 January 2021. Read 27 November 2026.
- Connects: Open Source Initiative, Elastic, MongoDB, Inc., Server Side Public License, The Open Source Definition
- Fact id: `osi-sspl-not-open-source-2021`

### 20 September 2023: On 20 September 2023 the Linux Foundation announced OpenTofu as an open source alternative to Terraform.

Step 4. The community response: an open source alternative under a foundation.

> Today, the Linux Foundation announced the formation of OpenTofu, an open source alternative to Terraform's widely used infrastructure as code provisioning tool.

- Source (primary, press-release): [Linux Foundation Launches OpenTofu: A New Open Source Alternative to Terraform](https://www.linuxfoundation.org/press/announcing-opentofu), The Linux Foundation, published 20 September 2023. Read 27 November 2026.
- Note: The OpenTofu manifesto, also read, says: "we created a fork of Terraform".
- Connects: The Linux Foundation, OpenTofu, HashiCorp, Business Source License 1.1
- Fact id: `opentofu-2023`

### 28 March 2024: Eight days later the Linux Foundation announced Valkey, which continues development from Redis 7.2.4 under the BSD licence.

Step 5. The same response to Redis.

> Valkey will continue development on Redis 7.2.4 and will keep the project available for use and distribution under the open source Berkeley Software Distribution (BSD) 3-clause license.

- Source (primary, press-release): [Linux Foundation Launches Open Source Valkey Community](https://www.linuxfoundation.org/press/linux-foundation-launches-open-source-valkey-community), The Linux Foundation, published 28 March 2024. Read 27 November 2026.
- Connects: The Linux Foundation, Valkey, Redis, BSD licence
- Fact id: `valkey-2024`

### 29 March 2024: On 29 March 2024 Andres Freund reported to the oss-security list that the xz compression library had been backdoored upstream, in a way that compromised SSH servers.

Step 6. The supply chain is attacked through an upstream project.

> The upstream xz repository and the xz tarballs have been backdoored.

- Source (primary, mailing-list): [backdoor in upstream xz/liblzma leading to ssh server compromise](https://www.openwall.com/lists/oss-security/2024/03/29/4), oss-security mailing list (Openwall), published 29 March 2024. Read 27 November 2026.
- Connects: Andres Freund, The xz backdoor
- Fact id: `xz-backdoor-2024`

### 29 August 2024: Banon wrote that using an OSI-approved licence was what allowed Elastic to use the term "open source" again.

Step 7. Elastic returns to an OSI-approved licence.

> But being able to use the term Open Source, by using AGPL, an OSI approved license, removes any questions, or fud, people might have.

- Source (primary, own-post): [Elasticsearch is open source, again](https://www.elastic.co/blog/elasticsearch-is-open-source-again), Elastic, published 29 August 2024. Read 27 November 2026.
- Connects: Shay Banon, Elastic, Open Source Initiative
- Fact id: `elastic-open-source-again-2024`

### 10 December 2024: The Act creates a new legal category, the open source software steward, for bodies that sustain open source products used commercially, under a lighter regime than manufacturers.

Step 8. European law defines open source stewards.

> the novel legal category of open-source software stewards is introduced. These are legal persons who provide support on a sustained basis for the development of such products which are intended for commercial activities, and who play a main role in ensuring their viability, and are subject to a light-touch and tailor-made regulatory regime.

- Source (primary, document): [The Cyber Resilience Act and open source](https://digital-strategy.ec.europa.eu/en/policies/cra-open-source), European Commission. Read 27 November 2026.
- Note: From the European Commission's explanatory page. The text of the Regulation on EUR-Lex returned a 202 challenge page and could not be read with the fetch tool.
- Connects: European Union, Cyber Resilience Act (Regulation (EU) 2024/2847)
- Fact id: `cra-open-source-stewards`

### 10 December 2024: The Commission says only open source software supplied in the course of a commercial activity falls within the Act.

Step 9. Non-commercial open source stays outside the law.

> only free and open-source software that is made available on the market, and therefore supplied for distribution or use in the course of a commercial activity, falls in scope of the Cyber Resilience Act.

- Source (primary, document): [The Cyber Resilience Act and open source](https://digital-strategy.ec.europa.eu/en/policies/cra-open-source), European Commission. Read 27 November 2026.
- Connects: European Union, Cyber Resilience Act (Regulation (EU) 2024/2847)
- Fact id: `cra-non-commercial-out-of-scope`

### 28 October 2024: On 28 October 2024 the Open Source Initiative released version 1.0 of its Open Source AI Definition.

Step 10. The OSI defines open source AI.

> After a year-long, global, community design process, the Open Source Definition (OSAID) v.1.0 is available for public use.

- Source (primary, press-release): [The Open Source Initiative Announces the Release of the Industry's First Open Source AI Definition](https://opensource.org/blog/the-open-source-initiative-announces-the-release-of-the-industrys-first-open-source-ai-definition), Open Source Initiative, published 28 October 2024. Read 27 November 2026.
- Note: The release sentence says "the Open Source Definition (OSAID)"; the document released is the Open Source AI Definition.
- Connects: Open Source Initiative, The Open Source AI Definition 1.0
- Fact id: `osaid-1-0-2024`

### 28 October 2024: The Open Source AI Definition requires detailed information about the training data, enough for a skilled person to build a substantially equivalent system, but not the training data itself.

Step 11. It asks for information about training data.

> Data Information: Sufficiently detailed information about the data used to train the system so that a skilled person can build a substantially equivalent system.

- Source (primary, document): [The Open Source AI Definition 1.0](https://opensource.org/ai/open-source-ai-definition), Open Source Initiative, published 28 October 2024. Read 27 November 2026.
- Note: That the data itself is not required is the reading of the definition's text and is the point its critics attack; see the Software Freedom Conservancy and FSF facts.
- Connects: Open Source Initiative, The Open Source AI Definition 1.0
- Fact id: `osaid-data-information`

### 22 October 2024: A week earlier the Free Software Foundation had said its own criteria for free machine learning applications would require the raw training data to carry the four freedoms.

Step 12. The FSF wants the data itself.

> it is working on a statement of criteria for free machine learning applications, which will require the software, as well as the raw training data and associated scripts, to grant users the four freedoms.

- Source (primary, press-release): [FSF is working on freedom in machine learning applications](https://www.fsf.org/news/fsf-is-working-on-freedom-in-machine-learning-applications), Free Software Foundation, published 22 October 2024. Read 27 November 2026.
- Connects: Free Software Foundation, The Open Source AI Definition 1.0
- Fact id: `fsf-ml-training-data-2024`

### 31 October 2024: The Software Freedom Conservancy's Bradley Kuhn criticised the definition for not requiring public disclosure of training sets, and said the OSI should not have published it yet.

Step 13. The Software Freedom Conservancy says the definition erodes the term.

> the OSAID fails to require reproducibility by the public of the scientific process of building these systems, because the OSAID fails to place sufficient requirements on the licensing and public disclosure of training sets

- Source (primary, own-post): [Open Source AI Definition Erodes the Meaning of "Open Source"](https://sfconservancy.org/blog/2024/oct/31/open-source-ai-definition-osaid-erodes-foss/), Software Freedom Conservancy, published 31 October 2024. Read 27 November 2026.
- Connects: Software Freedom Conservancy, Open Source Initiative, The Open Source AI Definition 1.0
- Fact id: `sfc-osaid-criticism-2024`
